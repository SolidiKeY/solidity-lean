# Browser runtime integration

This page is a client of the existing bundled `web/browser/worker.mjs`, not a replacement verifier. It sends `{id, method, params}` messages, awaits `runtime.params.proofReady`, opens `Playground.sol` with an increasing version, and requests `verify`. Replies contain `{id,result:{results,errors}}` or `{id,error}`. Function ranges are zero-based UTF-16 LSP ranges. `proved` is displayed as proved, `refuted` as wrong with the returned model state, and all other statuses as unknown. Ordinary executable results are trusted decisions, not fresh Lean kernel certificates.

The runtime consumes solc AST, not Solidity text directly: its worker runs the extension's pinned soljson 0.8.34+commit.80d5c536 compiler (SHA256 c8649f8d57f81b3244c7d2dd662efc0620d1ae296f623b347a2c616a6cfd11d8), then existing executable AST decoding, intrinsic elaboration and compact obligation checking. Admission is defined by `Solidity/Frontend/ExecutableAst/Shared` and `Solidity/Tools/DirectRuntime.lean`: specification-bearing public/external functions, supported intrinsic types, expressions, statements and bounded proof rules. Admission is not a proof. Unsupported AST, unsupported obligations, exhausted budgets and undecided checks stay unknown. Annotated loops may use existing exact-unrolling retries. No broader Solidity support is claimed here.

## Missing deployment dependency

The source checkout and static Pages exporter do not provide a loadable verifier at `/browser-worker.js`. The existing loader also requires origin-root `/compiler/soljson-v0.8.34+commit.80d5c536.js`, `/direct-worker.js`, and `/direct/{build.json,direct.js,direct.wasm}`, with matching source freshness metadata and license notices. Its absolute paths cannot be rebased for a Pages subpath inside the site's lease. A deployment owner must supply the already built, matching browser distribution and correct its base-path configuration outside this assignment. This task never rebuilds the runtime or compiler. Missing assets produce an explicit unknown error, never a simulated proof.

The shell, examples, editor and compressed source links work offline after the service worker finishes its first installation over HTTPS or localhost. A first visit needs static hosting; no application server is used. Verification offline additionally depends on the existing runtime deployment's own asset caching. Stub tests exercise the documented transport and presentation only; they do not establish real Solidity verification or compiler/runtime correspondence.

## Decoder inventory (base b1d088bde)

`Shared/Translate.lean` initially decodes uint256/int256/bool primitives, fixed/dynamic arrays and mappings with primitive keys; later guarded adapters retain narrow integer, bytes and address spellings in supported local contexts. This is context-sensitive admission, not support for all uses of these Solidity types. Expressions include numeric/boolean literals, identifiers, indexing, guarded member access (including environment members), supported binary operators, unary minus/not/bitwise-not and conditionals. Units, strings and arbitrary expression calls are not accepted by this initial decoder. The downstream adapters may accept additional guarded cases; rejection remains unknown.

Statement decoding handles blocks, unchecked blocks, variable declarations, returns, if/else, while/for/do-while, break/continue, assignment and admitted compound assignments, delete/increment/decrement, assert/require with one argument, and array push/pop. Arbitrary member calls and non-builtin calls are rejected by this initial path. The Identity example includes a caller to expose unsupported-function reporting alongside its specified identity function.

Specification comments use `@custom:key`, including `ensures` and `requires`; expressions include `\result`, `\old(...)`, primitive `\forall type name; ...`, booleans, integer literals, names, indexing, field selection, parentheses, negation and the admitted arithmetic/comparison/logical operators. Loop annotations use the existing invariant/decreases/unwind rules. The authoritative supported set is the decoder plus intrinsic elaborator at the matching build; this inventory does not bypass their guards or promise a decision for every decoded program.

Run `node --test scripts/site/*.test.mjs` and `node scripts/site/smoke.mjs`. If Playwright is installed outside module resolution, set `PLAYWRIGHT_MODULE` to its absolute `index.mjs`; `CHROMIUM_PATH` optionally selects installed Chromium. The smoke runner always labels its verifier as a stub and checks shell offline reload separately from verifier availability.
