# Coordinator tools

gate.sh runs from the current checkout: `gate.sh per-file FILE...`, `gate.sh touched`, `gate.sh checkpoint`, or `gate.sh full`. It writes one status line per gate and `gates.tsv` plus individual logs under `GATE_LOGS` (default a temporary `coord-gates` directory). It also writes `HEAD` (the commit the gates ran on), which handoff.sh checks. `GATE_BASE` selects the touched comparison base (default `origin/master`); touched modules are the Lean files changed since its merge-base with HEAD, renames counted as delete plus add, plus untracked files, and their reverse import closure. Relative FILE and `GATE_LOGS` paths are taken from the caller's directory. Exit 0 means all gates passed, 1 means at least one failed, and 2 means invalid usage or setup.

`seal.sh DIR [BASE]` creates a bundle of BASE..HEAD (default `origin/master`; when BASE is not an ancestor of HEAD, its merge-base with HEAD is the recorded base), a manifest, and SHA256SUMS, then verifies the seal. `seal.sh --verify DIR` checks file inventory, hashes, bundle tip, that the bundle's prerequisites are the manifest base or its ancestors (the base itself among them), and pack integrity. It uses `TMPDIR` for the temporary indexing repository. Exit 0 indicates success; nonzero indicates invalid usage, an empty range, or verification failure.

`handoff.sh [NOTES-FILE]` writes HANDOFF.md and CLOUDVM-RESULT.json and prints the JSON result. Set `HANDOFF_OUT` for the output directory (default `$TMPDIR/coord-handoff-<head>`, outside the checkout), `HANDOFF_BATCH`, `HANDOFF_SLUG`, `HANDOFF_BASE` (default origin/master), `HANDOFF_STATUS` (default partial), `HANDOFF_CHECKPOINTS` (comma-separated name=status), and `HANDOFF_GATES` (colon-separated gate log directories). Exit 0 means written; nonzero means invalid inputs or a refused done status. Done requires passing gates and a clean tracked tree, and is refused when a gate directory's `HEAD` (written by gate.sh) is not the current HEAD.

`disk.sh [--free]` reports free disk and cgroup memory. `--free`, or free space below `DISK_MIN_FREE_BYTES` (default 2 GiB), removes exited containers, extra worktree builds (only a real `.lake/build` inside the worktree, never one reached through a symlink), and older verified seals only; a seal directory holding a file that SHA256SUMS does not list is kept. Without cgroup files the ram line reads `unavailable`. Set `DISK_REPO`, `DISK_CGROUP`, and colon-separated `DISK_EVIDENCE_ROOTS` to choose the repository, cgroup and evidence roots. Exit 0 means the report/cleanup completed; nonzero means invalid usage or an error.

`try-tactics.sh MODULE GOAL [CANDIDATE...]` checks the standard tactics followed by supplied candidates against a proposition file or the type of a declaration name. With the lake backend it writes scratch files outside the checkout (`TMPDIR` chooses their parent); the mcp backend needs a temporary `TerraTry*.lean` at the checkout root, removed on exit (a killed run can leave it). It prints one result and log path per attempt; a candidate that leaves `sorry` FAILs. `TRY_TACTICS_BACKEND` selects the backend (lake, mcp, or auto). Exit 0 means at least one passed, 1 means none passed, and 2 means invalid usage or, with none passed, a lean-mcp bridge error.

`lean-mcp start|stop|status|tools|call TOOL JSON|diag FILE|goal FILE LINE|try FILE LINE TACTIC...` maintains a checkout-specific MCP daemon, starting it on demand. `LEAN_MCP_SOCKDIR` chooses its socket directory, `LEAN_MCP_SERVER_CMD` overrides the server command, and `LEAN_MCP_IDLE` sets idle seconds (default 7200). Exit 0 means success, 1 means a failed tool/diagnostic or no successful tactic, and 2 means a bridge or usage error. Stop the daemon after use. `try-tactics.sh` uses the bridge when `TRY_TACTICS_BACKEND=mcp`, or with auto when the daemon is running.

`register.sh [MODULE...]` registers specified modules, or all unreachable Solidity modules when none are specified, in the current checkout. `register.sh --check` lists orphans without writing. It excludes `Solidity/Scratch/`. Exit 0 means successful registration or no orphans, 1 means orphans in check mode, and 2 means invalid input or another error.
