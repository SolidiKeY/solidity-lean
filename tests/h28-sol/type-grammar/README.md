# H28 type grammar controls

This directory contains external grammar controls and proof-audit evidence.
They do not establish whole compiler correctness or full AST equivalence.

The exact compiler version/hash/URL are in fixtures.json and
solc-download.json under evidence. The verified compiler currently resides at
/workspace/scratch/h28-type-grammar/solc/soljson-v0.8.38+commit.1835d247.js.
The runner mounts it read-only, without network, and verifies its hash/version.

Run from the checkout, with no active MCP session:

```sh
python3 tests/h28-sol/type-grammar/run_bounded.py solc
python3 tests/h28-sol/type-grammar/run_bounded.py lean-fixtures
python3 -B tests/h28-sol/type-grammar/test_fixture_coverage.py
python3 tests/h28-sol/type-grammar/run_bounded.py axioms
python3 -B tests/h28-sol/type-grammar/check_signatures.py
```

The runner acquires writer.lock itself; do not wrap it in a second flock.
It keeps one heavy runtime active, 12 GiB/no swap and four GiB headroom.
The Lean execution gate preflights exact current receipt/source/case coverage.
Its IO evaluation calls the actual read-only parseType; no parser is mocked.
The standalone gate is the documented fallback when MCP's server overhead
hits the unchanged headroom guard.

All fixture sources and exact type strings are generated by generate_fixtures.py.
Regenerate only while holding the repository writer lock; rerun solc, coverage
and Lean gates afterwards. Failed intermediate extraction/phase assumptions
and the resolved finder/skeptic findings are retained in evidence. Every
constructor/field/fixture is enumerated in fixtures.json and inventory.json.

Final policy validation uses the actual unmodified repository gate:

```sh
python3 -B tests/h28-sol/type-grammar/final_policy.py full
python3 -B tests/h28-sol/type-grammar/final_policy.py build
python3 -B tests/h28-sol/type-grammar/final_policy.py solkey
```

The latter commands run the original default targets plus SolkeyTestSuite and
actual check-solkey separately when run-lean stops at reserved registration.
They do not waive that failure. The dedicated final-bin/lake wrapper serializes
the corpus runner's actual parallel Lake invocations, preserving all arguments
and adding explicit -j1/stack bounds. Runtime targets stay unchanged. Exact
commands, source hashes, resource bounds, failures and recoveries are in receipts.
The repository-pinned SolKey manifest/pin are used unchanged via read-only mounts.
