# Guarded audit acceptance

Regression guarded: a truncated census must not shrink the coverage denominator, failed validation must not erase a prior aggregate, and current runtime fingerprints must not masquerade as historical import provenance.

The additive guarded_acceptance.py entrypoint authenticates the complete frozen census before creating output. It requires explicit expected Lean-binary and import-manifest fingerprints, checks current manifest-listed toolchain files, and checks the binary identity in every receipt. Expected fingerprints are caller-supplied trust inputs, not approvals granted by this script. A nonempty manifest alone does not establish full import coverage.

The default path runs the existing acceptance.py with --require-complete in a fresh external evidence view. The validated receipt ledger is copied as a regular file and hashed, so a later change to the source ledger cannot change the gate input. Artifacts retain their original paths and existing hash checks. Atomic no-replace publication preserves prior aggregates. Original evidence and source files are not edited. Run this entrypoint under the repository writer lock; use a fresh external --out directory. Its --help lists the required census, baseline, frozen root, toolchain and expected-fingerprint arguments.

Current fingerprint agreement cannot reconstruct old compile inputs. If receipt-level toolchain_manifest_sha256 binding is absent or differs, historical import provenance is explicitly UNVERIFIABLE. Existing gate failures are retained; even a legacy exit0 becomes exit89 while that hold remains. --preflight-only is explicitly limited to current fingerprint/census checks and never reports proof, trust-policy or migration acceptance. Old receipts must not be retroactively annotated to fabricate historical provenance.
