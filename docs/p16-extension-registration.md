# P16 extension registration

[`Solidity/Yul/Interfaces/P16.lean`](../Solidity/Yul/Interfaces/P16.lean) is
generated from fragments by the [P16 generator](../scripts/h62/item1/p16-generator/generate.py). This page holds
the instructions for registering extensions and for checking the generated file.

## Proposed extension registration

This proposal requires VY1/VY3 agreement before integration. Each addition uses
one `VY1-Name.json` or `VY3-Name.json` in [`registrations/`](../scripts/h62/item1/p16-generator/registrations)
with exactly these fields:

```json
{"module": "Solidity.Yul.Name", "documentation": true}
```

`module` may be null, and `documentation` may be false, but not both. A module
requires [`imports/`](../scripts/h62/item1/p16-generator/imports)`ext-VY1-Name.txt` (or VY3), containing exactly
its module name and LF. True documentation requires [`body/`](../scripts/h62/item1/p16-generator/body)`ext-VY1-Name.txt`
(or VY3), containing exactly one nonempty balanced Lean doc comment and final LF. A
registration and its matching files are one change. The source module must exist.
Owner prefixes are names, not authentication. The owner must allocate a unique
Name within its prefix; a same-path Git conflict must be reviewed, not silently
resolved. Duplicate imports across all owners and the baseline are rejected.

Baseline nodes retain their original order. Proposed extension names sort
lexically after the baseline, first by owner key then by Name, independently
for imports and documentation. Owners must agree that this order is semantically
and operationally acceptable. Additions omitted from both registration and
interface cannot be discovered by this tool: compare the live owner deltas to
registrations. Registration edits and changes to baseline hashes
([`baseline-inventory.json`](../scripts/h62/item1/p16-generator/baseline-inventory.json)) require review.
The baseline check requires the pinned base commit to exist in the local Git
object database. Registration names grant no ownership or authority to change statements.
H82 permits statement-preserving marker maintenance; producer membership and
extension ordering still require separate reconciliation.

## Checking the generated file

The production P16 file carries the generated marker. Run
`python3 -B scripts/h62/item1/p16-generator/check.py` from any directory to
check complete generated bytes, the ordered node census and frozen Git baseline.
The baseline commit must be available locally. The marker changes no import or
documentation block. The marker-only patch remains a frozen migration fixture.

The checkpoint and full gates ([`gate.sh`](../scripts/coord-tools/gate.sh)) run
this checker as `p16-generated`. Their Git checkout must contain pinned baseline
commit `c6f550e281a7e5affa9a99bc2cdaed556dec00e4`; a missing object fails closed.
The retained gate patch records the reviewed registration delta. The synthetic
Python fixtures normalize only the exact optional marker and do not validate
live producer completeness or Lean semantics. New extension membership/order
still requires producer reconciliation; the adopted marker does not approve it.

Git-backed checks read immutable objects with replacement refs disabled.
The production checker also clears inherited Git routing/configuration variables.

## Tool reference

All tools live in [`scripts/h62/item1/p16-generator/`](../scripts/h62/item1/p16-generator) and run with `python3 -B`.

| Tool | Use |
|---|---|
| [`check.py`](../scripts/h62/item1/p16-generator/check.py) | Integrity check (no arguments): `generate.py --migration --check`, then `census.py`, then `census.py --baseline`. Not producer completeness, Lean elaboration or semantic adequacy. |
| [`generate.py`](../scripts/h62/item1/p16-generator/generate.py) | Exactly one of `--check` (compare to P16), `--render` (print expected bytes), `--patch` (unified diff to expected); `--migration` includes the generated marker. Never edits the owner-controlled file. |
| [`census.py`](../scripts/h62/item1/p16-generator/census.py) | Reconcile a P16 interface (`--target PATH`, default the live file) against registered import and doc nodes; `--baseline` compares baseline fragments to the pinned Git commit. |
| [`conservation.py`](../scripts/h62/item1/p16-generator/conservation.py) | Account for an owner interface delta against registrations: `--after PATH` or `--after-rev SHA` (full owner commit containing P16); `--owner VY1\|VY3\|integrated` (default `integrated`). |
| [`producer_inventory.py`](../scripts/h62/item1/p16-generator/producer_inventory.py) | List every changed Yul Lean file at a descendant commit: `--head SHA` (full lowercase) `--owner VY1\|VY3`. |
