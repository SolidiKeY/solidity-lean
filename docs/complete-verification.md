# Declaration certificates and exact counterstates

This work ports the useful chain from mini-solkey's declaration certificates,
no-information-loss reductions and countermodel reconstruction. The supported
source fragment now has an exact proof-or-counterstate backend, connected to
`#verify`. Successful recognition carries original-formula equivalence;
complete arithmetic decision returns either verdict. Unsupported constructs
and operational resource limits retain the existing strategy and heuristic
search. This is not completeness for all Solidity or reachable-state validity.

## Declaration facts

`Calculus/DeclarationFacts.lean` certifies the actual ranges generated by
`SurfaceSpec.lean`: scalar roots, struct fields and quantified mapping
entries, including signed and boolean mapping keys. `declaration_facts[C]`
runs the existing declaration compiler and quotes its formula;
`sol_decl_facts` builds an ordinary Lean proof of that formula. A compilation
error is reported. The certifier has a shared node budget and catches a
timeout on each attempted rule.

The mathematical reason is intrinsic typing plus total declaration paths.
`Path.Declared` permits fields and mapping keys, but no array index.
`Tm.Total` and `Tm.Declared` establish that the relevant reads return; their
values already carry their Solidity bounds. This proves ranges for every
typed storage, not that every typed storage is canonical, reachable, or
`wt(storage)`.

`Tools/Counterexample.lean` uses these certificates when a function-spec
candidate cannot be certified by direct three-valued evaluation. It proves
every precondition conjunct and the false body separately, then transports
failure through the original parameter peeling. It does not drop mapping
premises or replace a universal quantifier with a finite set of keys. A
computed boolean guard precedes construction of each evaluator proof, and
the final theorem is checked by the kernel. `Examples/Verify.lean` pins a
previously tested mapping counterexample as certified, and rejects a false
quantified premise and an array-index range.

`Calculus/DeclarationReduction.lean` now connects those facts to exact
read reduction. `declaration_reduce[φ]` produces a normalized formula with
an equivalence proof in every typed state. A certified fact becomes `true`;
neutral conjunctions and implications are simplified, also beneath typed
universal binders. Failed certification and structural-budget exhaustion
retain the original subformula. Each declaration attempt has its own
bounded certifier search; the structural traversal shares a node budget.

`declaration_read_reduce[φ]` composes this certificate with the exact read
recognizer. `DeclarationReadReduction.countermodel?` therefore returns a
counterstate to the original formula, with its generated premises still
present in the certified conclusion. `Examples/DeclarationReduction.lean`
checks generated facts, typed parameters outside an implication containing
quantified mapping ranges, retained user requirements, false requirements,
and rejection of a false quantified premise. This closes the previous
declaration-premise normalization gap for this logical fragment.

## Exact reduction and finite reads

The existing `Fml.toLS` is directional: positive reduction suffices to prove
a formula, while negative reduction follows from it. A pending modality can
become `false` positively. Consequently neither that leaf nor
`Seq.checkCore = some false` supplies a semantic refutation.

`Calculus/ExactReduction.lean` computes both directions and accepts only
structurally equal complete typed leaves. `ExactReduction.holds_iff` proves
per-state equivalence; `elim_holds_iff` composes the existing exact
read-of-write elimination. This initial recognizer rejects every pending
program, update and hidden binder rejected by negative reduction. It does
not change the existing closer or symbolic executor.

`Calculus/ReadRealization.lean` materializes finite typed primitive reads by
the interpreter's actual successful saves. `Assignment.realizable_iff`
states precisely that agreeing values at aliased actual references are
necessary and sufficient for a finite assignment to have a typed storage
representative. Different endpoint primitive types are handled together.
References are compared computably; `Option.get` uses a proved successful
save rather than a failure fallback.

`Calculus/ReadQuery.lean` records dependencies between reads. For
`balances[balances[3]]`, the inner value determines the second reference.
`Query.run_realize` proves that realizing the selected finite footprint
preserves the result and every later reference selection. Only the selected
continuation is followed; mapping keys are not enumerated.

`Calculus/QueryReduction.lean` connects this interface to the existing typed
`LTm` and `LFml`:

- `ReadExpr.ofTerm?` recognizes primitive atoms, literals and transaction
  values, declaration paths, mapping indices, primitive observations, checked
  unary/binary operators, and the reducer's guards and failing terms.
  `ReadExpr.query_sound` preserves their actual optional evaluation.
- `ReadFormula` handles quantifier-free Boolean combinations of defined
  equalities. Two failing terms do not become equal.
- `ReadSentence` adds a universal prefix. Typed argument lists choose
  instances; malformed or missing entries choose the primitive default.
  `argument_cons` and `holds_of_queries` prove that every typed instance is
  represented. This is not a finite-sampling proof of a universal claim.
- `ReadReduction.valid_iff` states the full source-to-query equivalence on
  this recognized fragment, over all original starting states, all typed
  argument choices, and all valuations of actual typed locations.
- `ReadReduction.countermodel?` rejects inconsistent aliased occurrences,
  checks a **supplied** finite assignment and
  returns a typed state together with a proof that the original scoped
  formula is false when the selected instance fails.

Compiled queries can conservatively include reads of an unused pure
operand. Their values still preserve short circuit semantics by the
evaluation theorem. No source program effects are evaluated by this query
interface. The state returned for a quantified counterexample has context
`[]`; its argument list witnesses failure of the universal sentence, rather
than adding parameter locals to the state.

`Examples/ReadRealization.lean`, `Examples/ExactReduction.lean` and
`Examples/QueryReduction.lean` pin alias agreement/conflict, mixed primitive
values, rejection of directional fallbacks, dependent mapping keys, mixed
typed quantified parameters, fields beneath signed/boolean mapping keys,
failure of defined equality, conservative unused reads, and unsupported
arrays, memory, ledger reads and interior quantification. The headline
equivalences and counterstate transport use only Lean's standard three
axioms (`propext`, `Classical.choice`, `Quot.sound`).

## Bounded occurrence traces and source countermodels

`Calculus/ReadTrace.lean` accepts a stream of typed occurrence values.
`Query.replay` uses each value to select the next actual declared location,
so a nested read needs no enumeration of mapping keys. `replay_bind`
advances the continuation by the prefix's actual selected trace length.
Skipped reads consume no position. These are leaf-query occurrences;
as above, a compiled query can include an unused pure operand.

The finite assignment records every selected location and value.
`replay_realizable_iff` proves that alias consistency is necessary and
sufficient for an actual storage representative agreeing with every
occurrence and preserving the result. Agreement on the final Boolean alone
would be weaker and is not the realization condition. `record` and
`replay_record` provide the converse: every actual storage run has a
consistent finite occurrence witness. `all_storage_iff_traces` therefore
preserves both directions of the validity question.

`Calculus/QueryReadBounds.lean` proves syntax-derived finite bounds for
`ReadExpr`, `ReadFormula` and universal-prefix `ReadSentence` queries.
The bounds hold for every occurrence stream, start position and selected
branch. They conservatively sum alternatives; replay still advances by
the actual trace length. `replay_storage_exists_bounded` combines that bound
with the no-loss witness theorem.

`Calculus/TraceReduction.lean` composes exact program/update normalization
with these queries. `TraceReduction.valid_iff` states original-source
validity over all states, typed parameter instances and consistent replay
streams. `countermodelFromTrace?` checks aliases and a false replay before
materializing actual storage and proving the original claim false.
`countermodelFromValues?` takes a finite `List CallValue`; missing or
mismatched entries select the requested type's default. The final replay
check still certifies the original formula. Neither interface chooses the
values automatically.

`declaration_trace_reduce[φ]` adds certified declaration normalization.
That normalization now traverses hidden `Fml.bind` binders as well as
explicit quantifiers, which is necessary for generated mapping premises
beneath real function parameters. Unsupported quantified user requirements
remain present and can prevent recognition.

`Examples/ReadTrace.lean` checks a nested-read formula, an actual parameterized
`follow` function and their reconstructed initial values (`balances[3] = 4`,
`balances[4] = 19`), mixed typed occurrences, skipped-read cursor composition,
and consistent/conflicting self-aliases through the original-source API.
It also checks that a false quantified user requirement is retained.
`Examples/CompleteVerification.lean` checks automatic exact verification of
a mapping setter whose parameter binder encloses generated mapping ranges.
Arithmetic selection of dependent-read values has the certified-query
interface below and the automatic source compiler described under
"Automatic dependent-read decisions".

## Arithmetic extraction from typed query certificates

`Calculus/QueryArithmetic.lean` connects dependent read occurrences to
the existing complete arithmetic solver. `Query.HasLayout` requires an
exact finite sequence of primitive occurrence types for every proposed
value stream. Locations can depend on earlier values. The current layout
does require fixed occurrence count and types, so it does not cover queries
whose selected branches change that sequence.

`Assignment.vector` retains every occurrence value in a heterogeneous
`ScalarCode.Values` vector. `replay_self` and `finite_replay` prove that
every proposed stream has such a finite representative, preserving the
whole result and trace even before checking alias consistency. No Solidity
domain or mapping key is enumerated by this representation.

`Query.Arithmetic` supplies that layout and a typed arithmetic formula,
together with an equivalence between the formula and the implication
from trace consistency to a true result. The formula must include all alias
constraints needed for that equivalence. `Arithmetic.valid_iff` proves
complete arithmetic validity equivalent to validity over all actual storage.
`Arithmetic.verify` therefore returns either that validity proof or an actual
typed counterstore. A false guarded arithmetic assignment entails both alias
consistency and a false result; inconsistent independent occurrence values
cannot become a negative verdict.

`Tools/QueryArithmetic.lean` provides `query_countermodel[certificate]`.
Compiled graph exploration chooses finite natural codes once. The kernel
then checks the guarded finite assignment and the reconstructed counterstore's
actual query refutation. The exported `queryCountermodelOfCodes` helper
independently applies that same check to supplied codes. The shared
`Tools.checkCertificate` gate is also the existing exact verifier's gate.
The source bridge `TraceReduction.countermodelFromQuery` transports an
actual query counterstore through the original program/update equivalences
and universal sentence.

`Examples/QueryArithmetic.lean` supplies an explicit arithmetic certificate
for `balances[balances[3]] == 17`. The solver selects `(3,3)`, and the
reconstructed storage refutes that original scoped claim. A positive alias
law checks both verdicts. Conflicting `(3,19)` codes fail the independent
kernel gate, and a valid query is rejected by the countermodel elaborator.
A heterogeneous certificate forces the solver to choose `paused = true`
and signed `debt = -2` before the dependent unsigned reads; reconstruction
returns `(true,-2,3,3)`, testing all three primitive domains and shifted
occurrence positions together. Axiom pins contain only `propext`,
`Classical.choice` and `Quot.sound`.

The general certificate interface permits an explicitly supplied arithmetic
formula and equivalence. The generated alias stage below produces constraints
and arithmetic from symbolic reads. The automatic source compiler now adds
fresh occurrence generation, failed-path guards and storage reconstruction;
the explicit query certificate remains available independently.

## Generated symbolic path aliases

`Calculus/SymbolicPaths.lean` recognizes existing rooted `LTm` path terms as
the closer's `SPath`: roots, fields and indices, retaining every key as its
original term. `SPath.View.correct` preserves the complete optional evaluation
in every state and atom environment. It does not assert key success, array
presence or declaration-path membership. Recognition has a depth budget of
1024; exhaustion and unsupported syntax return `none`.

`Calculus/AliasConstraints.lean` reuses the closer's `relSegs` comparison and
its interpreter correspondence. `CTree.toFormula` translates its existing
key-equality case tree into Boolean combinations of defined equalities.
`toFormula_holds` requires the comparison's `TestsOk` condition, preventing
two failed keys from being treated as a successful equality.
`SPath.alias_holds` proves the generated formula equivalent to actual typed
reference equality when both primitive paths evaluate successfully and their
references are declared. Different roots, fields and endpoint types retain
their existing interpreter meaning.

`aliasCondition?` composes source-path recognition with that formula.
`aliasEncoding?` also invokes the shared checked arithmetic compiler.
`AliasEncoding.correct` retains both successful-path premises and the
compiler's actual finite input/reference layout. Checked key arithmetic keeps
its range and failure conditions; unsupported key expressions return `none`.

`SymbolicRead` records a symbolic path and its typed result term, normally a
fresh occurrence atom. Its generated pair constraint says equal locations
have equal results. The `Witness` interface requires both path and result
evaluation to succeed. `constraints` emits all ordered pairs; with `n`
occurrences it generates `n²` pair conditions, each using the existing path
comparison. This expansion has no independent size cutoff in the mathematical
API; the automatic source compiler below checks a pair-count budget before
constructing that matrix, alongside its occurrence-generation budget.
The existing bounded key-expression recognizers can reject unsupported or
over-budget expressions during arithmetic compilation.

`SymbolicRead.constraints_realized_holds` proves the generated finite
conjunction exactly equivalent to `Assignment.Consistent` on its successful
typed occurrences, including duplicates, self-pairs and mixed endpoint types.
It connects the generated arithmetic to the trace-realization interface
without assuming that independent occurrence values are actual storage.

`Examples/AliasConstraints.lean` replaces the earlier explicit arithmetic
formula for the nested mapping claim with generated constraints followed by
the existing compiler. The solver again chooses `(3,3)`, reconstructing an
original-source counterstate. Tests cover source path terms, checked key
overflow, signed and Boolean keys under mapped struct fields, different
fields/roots/types, conflicting self-aliases, and missing witnesses for failed
keys or results. A three-occurrence example uses locations `3,4,3`; generated
arithmetic certifies the consistent subset of aliases, rejects a conflicting
third value, and realizes the requested actual storage. Axiom pins use only
Lean's standard three axioms.

The automatic compiler below supplies result atoms, occurrence layouts and
guards. Its generated constraints differ from the unguarded mathematical
API above: failed paths impose no alias condition.

## Automatic dependent-read decisions

`Calculus/PathGuards.lean` recognizes declaration paths through roots, fields
and mappings. The guard returns `true` exactly when the path returns; a
failed checked key stays failed. Arrays remain outside this guard fragment.

`Calculus/FlattenReads.lean` replaces primitive observations by fresh typed
atoms preceded by those guards. It collects potential reads in dependency
order, including unused pure alternatives. Existing source positions at all
primitive types determine the fresh starting position. Sibling terms and
formula branches share one node budget, with a separate depth bound.
The local equivalence requires each successful occurrence to denote the
actual storage word; it makes no assertion about failed occurrences.

`Calculus/ReadFree.lean` obtains executable terms and formulas from the
existing query compiler. A zero read bound proves storage independence.
`Calculus/OccurrenceLayout.lean` checks consecutive result slots, a read-free
path for each occurrence, and that its keys use only earlier atoms.
`fill_agrees` and `fill_interpreted` prove every actual state supplies those
fresh results without changing its inputs. Conversely, `entries` records
only successful paths; `realize_interpreted` reconstructs every consistent
active assignment using the interpreter's actual saves. Replacing storage
cannot change the selected paths because their terms are read-free.

`Calculus/ReadFlattening.lean` joins those directions. Its `valid_iff` is
original leaf validity iff the flattened leaf holds under active-read
consistency, over all typed states and atom environments.
`Calculus/ActiveReadConstraints.lean` generates the finite alias formula and
proves it exactly equivalent to that consistency condition. Both paths must
return before an alias condition applies; two failed keys do not become a
successful read or equality.

`Calculus/LeafArithmetic.lean` collects the actual typed atoms and observed
environment fields and invokes the shared checked compiler. The compiler
checks the quadratic pair count before generating the alias matrix.
`FlattenedArithmetic.valid_iff` proves complete arithmetic validity exactly
equivalent to original leaf validity. Its negative branch materializes actual
typed storage, rather than leaving independent occurrence values as a model.
`Tools/LeafArithmetic.lean` offers `leaf_countermodel[certificate]`, with an
independent kernel check of the reconstructed original-leaf refutation.

`Calculus/LeafInputs.lean` proves agreement on the typed input positions a
term actually uses. `Calculus/DependentReduction.lean` checks that every
original body atom belongs to its universal parameter prefix, before fresh
read atoms are introduced. `body_valid_iff`, `valid_iff` and
`countermodelOfCodes` transport both verdicts through that prefix and exact
program/update normalization. `declaration_dependent_reduce[φ]` composes the
same independent declaration certification as the existing input compiler.
Generated mapping ranges disappear only by certified equivalence; user
requirements remain in the original conclusion.

`sol_exact` and `#verify` retain the existing static-input route first and
try this dependent route when necessary. Both verdicts and both report
helpers independently check the original proof in the kernel. Detailed
counterexample display certifies the actual original call; failed rendering
keeps a minimal report of the actual state and original parameters, excluding
fresh read slots. An early search of at most 512 graph rounds checks newly
discovered arithmetic nodes for a negative witness. This is not a node cap:
each frontier can still expand exponentially with arithmetic width.
Exhaustion falls back to the complete graph
decision and never means validity. In the scratch measurement, the mixed
function had two reads, five typed atoms and six arithmetic variables; the
early search reached a false node after 1,276 discovered nodes in about
nine seconds, while completing the full graph was still running after
several minutes. Positive replay still checks the complete decision.

`Examples/ReadFlattening.lean` checks automatic nested reads, alias conflicts,
mixed primitive storage values, high mixed-type source positions, failed and
overflowing keys, pure alternatives, and both node and alias-pair budgets.
`Examples/DependentReduction.lean` pins original-function positive/negative
reports, mixed Boolean/signed/unsigned parameters, minimal rendering, forged
code rejection and preservation of unsupported quantified user premises.
Headline axiom pins contain only Lean's standard three axioms.

Acceptance still depends on the complete compiler, not flattening alone.
In particular, flattening preserves numeric `orElse` and `kite` terms whose
arithmetic encoding can remain unsupported. Array presence/length, memory,
ledger reads, interior quantifiers, nonlinear arithmetic, remaining updates
and general reachability or calculus completeness remain outside this result.

## Complete arithmetic decision and guaranteed counterassignments

`Calculus/LinearDecision.lean` is a dependency-free local adaptation of
mini-solkey Chapter 19. Its arithmetic intermediate language has linear
equations and inequalities with integer coefficients/constants, over natural
variable assignments, combined with negation, conjunction and implication.
Inequality derivatives use floor division, including negative odd residuals;
they do not inherit the parity rejection used by equations.
`AFml.decide_iff` proves a total decision: true exactly for valid formulas.
`AFml.exploration_isSome` proves that the computed finite graph bound always
suffices, so the implementation's exhausted arm never supplies a false
semantic verdict. Explicit `simp only` proofs keep the port's rechecking
cost independent of later simp-set growth.

The algorithm reads low bits and transitions to a derivative formula about
halved variables. Retained atoms keep their coefficients; arithmetic atoms and
logical structure can collapse to `true` or `false`, and constants stay
inside a proved finite universe. The reachable graph is valid exactly when
all its formulas hold at zero. It enumerates bit combinations of the
formula's finite variable width, not all possible natural assignments or
all 256-bit words. Its graph can nevertheless be exponentially large and
deduplication currently uses lists; mathematical termination is not a
practical time or memory bound. Keep explicit resource boundaries when
integrating it with tactics.

`Calculus/LinearCountermodel.lean` retains an assignment reconstruction
function with each discovered derivative node. `Node.explore_map` proves
that forgetting those functions gives precisely the original decision's
graph: same fuel, states and duplicate policy. A false zero test is
therefore an actual reachable node, and its reconstruction supplies a
counterassignment to the original arithmetic formula. `AFml.countermodel`
requires only a computed negative decision; it has no guessed witness bound,
small-value pool, or secondary search over natural assignments.
`AFml.countermodelValues` stores the relevant values as a finite list;
`countermodelValues_check` proves that padding it with zeros still falsifies
the formula. `AFml.verify` returns either a validity proof or a concrete
counterassignment from one traced graph traversal.

`Calculus/LinearSyntax.lean` provides macro-only arithmetic notation
(`linear!{ [2, -2] = 1 → false }`) and a printer in numbered variables.
Quotation equality is checked by `rfl`; this notation does not extend
Solidity's source formula language or change the meaning of `dl!{ … }`.

`Examples/LinearDecision.lean` computes parity validity, reconstruction of
17 with positive and negative coefficients/targets, a two-variable model,
constant formulas, implication, different atom widths, finite-list output,
upper-bound witnesses, odd/negative inequality targets, and both verifier verdicts. The decision and counterassignment theorems use
only Lean's standard three axioms. These are arithmetic guarantees: the
broader typed Solidity translation listed above is still required beyond
the automatic static-read fragment described next.

## Exact typed arithmetic and automatic static-read counterstates

`Calculus/ScalarCode.lean` gives bijective codes for each primitive domain:
Boolean `0`/`1`, unsigned values, and signed values shifted by `2^255`.
Both inverse laws are proved. `decode?` rejects out-of-range codes instead of
wrapping them or substituting a default. Its arithmetic domain constraint is
exactly successful typed decoding.

`Calculus/TypedLinear.lean` lifts this to heterogeneous finite contexts.
`TypedFormula.valid_iff` equates validity over typed vectors with validity
of the domain-guarded natural formula. Its width certificate ensures that
decoding the finite vector preserves every observed variable. A negative
complete decision necessarily satisfies the domain premise, so
`countermodelOf` decodes an actual false typed vector. `verify` uses one
derivative-graph traversal. These formulas describe **scalar codes**;
signed source arithmetic requires its own offset-aware translation.

`Calculus/ReadLayout.lean` observes distinct actual primitive references as
one such vector and realizes every vector by successful interpreter saves.
`Layout.observe_realize` proves exact readback, including mixed endpoint
types. Repeated or aliased occurrences must share a layout entry.

`Calculus/StaticLinear.lean` is the first complete automatic source bridge.
It recognizes logical combinations of equalities between primitive
literals, successfully evaluated closed primitive expressions, and declared
root/field/mapping reads with literal typed keys. Closed computations use
the interpreter's actual checked operators and retain a proof of successful
evaluation; failed or unsupported operands are rejected. Recognizing both
operands can conservatively reject a defined short-circuit expression.
It checks the candidate layout's actual-reference coverage and distinctness
and the compiled formula's variable width. `StaticFormula.compile_iff`
preserves the leaf in every state; its composition with exact reduction is
`StaticReduction.meaning`, about the **original** scoped formula.
`StaticReduction.verify` returns a proof of original validity or an actual
typed original counterstate without supplied values or a guessed search
bound. `valid_of_decide` and `countermodel` expose each certified direction.
Path and closed-expression recognition have depth budgets of 1024;
exhausted recognition returns unsupported. The complete arithmetic API remains potentially expensive,
so a tactic integration still needs resource limits and timeout handling.

`Calculus/DeclarationStaticReduction.lean` composes certified normalization
with this automatic source bridge: `declaration_static_reduce[φ]` produces
a `StaticReduction φ`, with all original declaration and user premises in
its conclusion. False quantified user premises remain unsupported.

`Examples/TypedLinear.lean` pins all codec endpoints and rejected codes,
Boolean domain code `2`, unsigned `17`, and mixed `(true, -2, 17)` decoded
counterassignments. `Examples/StaticLinear.lean` reconstructs unsigned `17`
and mixed `(true, -2, 17)` primitive stores from original formulas, checks
independent mapping locations and fields under signed/Boolean literal keys,
proves an alias equality
with one variable, and certifies a false Boolean original formula including
its generated quantified mapping premises. Dependent keys, source arithmetic,
quantifiers and pending programs are explicitly rejected by this initial
automatic recognizer. Broader read queries and supplied-assignment reconstruction
remain available in `Calculus/QueryReduction.lean`.

## Checked source arithmetic

`Calculus/CheckedScalar.lean` pairs an affine scalar code with its exact
successful-evaluation guard. `Correct` distinguishes `none` from `some v`:
failure requires a false guard; success requires a true guard and the exact
encoded value. `ScalarCode.inRange_iff` equates shifted signed/unsigned
bounds with the interpreter's actual `inRange` check. Checked addition
subtracts one signed offset from the sum of operand codes; subtraction adds
one offset to their difference. `arith_correct` retains both operand guards
and the result's bounds. `eq_correct` requires both computations to return,
so equal failures cannot produce true defined equality.

`Calculus/CheckedLinear.lean` connects these operations to existing typed
leaf terms. `CheckedValue` carries the finite actual references, the partial
scalar encoding and a proof against `LTm.eval` in every original state.
It recognizes total static values, checked signed/unsigned addition and
subtraction, and explicit failure. `StorageEncoding` composes leaf equalities
and logical connectives. `checkedReduction?` returns the same
`StaticReduction` certificate, reusing original-source proof/countermodel
transport, exact domain constraints and successful-save reconstruction.
Recognition has a term-depth budget of 1024; it does not infer that
unsupported arithmetic is false. Closed-constant recognition is currently
retried at expression nodes, so long nested expressions can repeat work;
profile before optimizing it.

`declaration_checked_reduce[φ]` composes the broader compiler with certified
declaration normalization. Both declaration term helpers share one compiler
composition and elaboration driver. Normalization and recognition each have
their own heartbeat accounting, without raising the configured limit. The
Boolean recognition guard uses compiled evaluation. Meta reduction through
a deep source recognizer can exhaust recursion despite a true result. The
returned `Option.get` includes its computation equality; the kernel checks
that equality when checking the resulting certificate. Compiled evaluation
is never accepted as proof by itself.

`Examples/CheckedLinear.lean` checks positive and negative arithmetic claims,
actual reconstructed value `17`, unsigned overflow/underflow, both signed
boundaries, and checked unsigned no-wrap. Both intermediate-overflow and
intermediate-underflow cancellation are tested: the final affine expression
can equal the input while an earlier operation still failed. An equality of
two identical failed closed expressions has an explicit kernel-checked
original counterstate and a `¬ Valid` theorem. Generated quantified mapping
facts and the retained user requirement also pass through the checked helper;
a false quantified user premise is rejected.

Interior quantifiers, dependent mapping keys, broader updates and remaining
source-program forms are outside these automatic decisions.
The existing query realization supports broader supplied assignments, but
that does not substitute for their automatic compilation or exact program
reduction.

## Comparisons and partial Boolean expressions

`Calculus/CheckedBool.lean` represents a Boolean expression by separate
predicates for successful `true` and successful `false`. A failing expression
satisfies neither predicate. `and_correct` and `or_correct` preserve source
short-circuit order: a successful false left operand of `&&` ignores right
failure, while a failing left operand still fails even if the right operand
is false. Boolean negation swaps the two success predicates; it cannot turn
failure into true. Boolean equality and inequality require both operands to
return successfully.

Numeric comparisons first remove the signed encoding offset from the
operands' affine codes, then compile the interpreter's integer comparison.
Both operand-definedness guards remain in both Boolean result predicates.
`comparison_correct` proves this for the actual optional operand values.

`BooleanValue` in `Calculus/CheckedLinear.lean` connects these encodings to
`LTm.eval`. Its recognizer handles numeric comparisons, Boolean negation,
conjunction/disjunction and strict Boolean equality/inequality. Leaf Boolean
equalities use the same two-success-predicate representation. The existing
`checkedReduction?` and `declaration_checked_reduce[φ]` APIs therefore return
proofs or guaranteed original counterstates for this larger fragment.
All operands must be recognized even when a short circuit could ignore one;
an unsupported operand can still cause recognition to return unsupported.

`Examples/BooleanLinear.lean` reconstructs `18` from the interval
`17 < balances[3] < 19`, checks signed comparison order, and reconstructs
zero from a failed subtraction used in a comparison. Paired Boolean tests
distinguish ignored right failure from retained left failure, and check
partial negation and strict equality with a constant left operand. The
declaration-normalized interval test retains the original generated premises.

## Exact update reduction

`Calculus/ExactUpdates.lean` constructs a typed state for every local-value
vector whose context has no memory locals. Values, storage aliases,
snapshots and KeY integers have representatives at the chosen global heap;
a memory identity may have none. `LocalRealization.getV_state` and
`glob_state` establish exactly the reads and global part of this landing
witness. The constructor never substitutes an invalid identity or changes
the heap to accommodate one.

`updateGuard_iff` proves the reverse implication missing from the ordinary
reducer, as well as the forward one. A push-free update cannot exhaust.
When it fails ordinarily, a box accepts failure and a diamond rejects it.
When it succeeds, the landing witness makes universal continuation truth
equivalent to the symbolic leaf. `ExactAt.update` obtains guard equality,
agreement and freshness from `Upd.toLS_sound` and composes the continuation
equivalence. Logical connectives and typed universal binders compose these
certificates. The recognizer has a depth budget of 2048 and rejects pending
programs, unsupported updates, memory-local destination contexts and every
push-bearing update; exhaustion is not reclassified as ordinary failure.

`sourceReduction?` exposes the resulting original-source equivalence.
`checkedReduction?` now consumes this certificate. `DefinedValue` and
`BooleanValue.seq` in `Calculus/CheckedLinear.lean` compile primitive guards
as successful evaluation, regardless of whether a successful Boolean result
is false. Arithmetic recognition still has to accept the resulting guards
and leaves; exact reduction alone does not ensure an automatic verdict.
In particular, arbitrary storage/memory guards are not newly supported by
this connection. Universal arithmetic parameters use the additional bridge below.

`Examples/ExactUpdates.lean` checks an identity-update counterstate, a
diamond underflow counterstate at zero, the corresponding valid box, a
failure-forcing premise with a false box continuation, a successful false
local, literal storage writes with both verifier verdicts, and parallel
bindings followed by a simultaneous swap. It explicitly rejects
memory-local destinations, a push-bearing update and a pending program.
Conjoined postconditions are parenthesized under their update: its
continuation binds more tightly than `∧` in the existing notation.

## Typed universal parameter decisions

`Calculus/ParameterLayout.lean` places a finite typed parameter vector before
the actual storage layout. A key retains its primitive type and its atom
position. Thus Boolean position zero and unsigned position zero are
independent. Storage indices begin at the parameter count. Duplicate
parameter keys and duplicate actual storage references are excluded before
independent arithmetic assignments are accepted.

`Parameters.observe_realize` reconstructs every typed vector as an actual
storage plus an `AEnv`, using successful storage saves and typed parameter
updates. `read_assign` and `observe_assign` prove that instantiating all
universal binders with a chosen valuation preserves every observed input.
They cover every typed value, with no finite sample of arguments.

`Calculus/CheckedLinear.lean` now shares its checked arithmetic, partial
Boolean and definedness proofs across parameter contexts. A variable is
recognized only with a membership proof for its typed parameter key.
Static storage codes shift by the parameter count. The existing
`checkedReduction?` API uses the empty context; the previous storage-only
observation is definitionally the same there. This extends the compiler
without copying the expression rules into a separate parameter compiler.

`Calculus/ParameterReduction.lean` strips a universal prefix and compiles
its body. `UniversalPrefix.close` and `instantiate` connect the complete
typed arithmetic interpretation to that original prefix.
`ParameterReduction.valid_iff` equates original validity with validity over
every typed input vector. `verify` returns either an original validity proof
or storage and parameter atoms with a false-instance certificate;
`Countermodel.refutes` proves failure of the original universal formula.
The countermodel retains the starting state at context `[]`: the failing
arguments are recorded separately. `countermodelOfCheck` cheaply checks an
already extracted finite vector rather than rerunning the complete graph
inside kernel reduction.

`declaration_parameter_reduce[φ]` composes this bridge with the same certified
declaration normalizer and bounded elaboration driver. Generated quantified
mapping ranges may occur beneath the parameter prefix; user requirements
remain in the exact conclusion. The prefix recognizer has depth budget 1024.
The body must still be in the shared checked fragment. Interior quantifiers,
dependent mapping keys, unsupported guards and pending programs return
unsupported rather than a semantic verdict.

`Examples/ParameterReduction.lean` extracts interval value `18`, joint
parameter/storage values `(17, 19)`, two same-type parameters plus storage
`(17, 23, 19)`, and mixed `(true, -2, 17)` arguments. It checks repeated
parameter reads, unsigned overflow, signed underflow, an update with a
parameter-dependent guard, declaration facts beneath a universal binder,
and different primitive types at the same atom position. An explicit check
of extracted value `18` also proves the original universal claim invalid.

## Exact source-program decisions

`Calculus/ExactRun.lean` bridges actual statement execution to its update.
Ordinary optional agreement alone does not supply the converse: it permits
divergence and exhaustion. `Upd.afterT_run_iff` adds an ending run and a
non-exhausted update. A successful actual run provides the typed landing
state; `Upd.Lands.eq` proves uniqueness, including any memory locals already
present. A reverted run retains ordinary box/diamond polarity. Panic,
divergence and exhaustion cannot be silently converted to ordinary failure.
`ExactStatement` packages this evidence for local/storage assignment,
storage deletion and primitive local declarations.

`Calculus/ProgramReduction.lean` reuses the pointwise formula-equivalence
certificate to normalize original programs. It traverses sequential, pop
and thinning frames, opens blocks and converts hidden primitive binders to
typed universal binders. `require` keeps its successful-true guard. `assert`
also rejects successful false, since that is a panic under either modality;
failure while evaluating its condition is instead a revert. A branch tests
successful true and successful false separately, so a failing condition
selects neither branch. The box accepts that revert and the diamond rejects
it. The unselected branch has no semantic effect.

`ProgramNormalization.ofFormula?` has a structural depth bound and a shared
node budget. Each rewrite, frame and logical child consumes from the same
counter, including both branches and their duplicated continuations.
Budget exhaustion and unsupported statements return no certificate.
`programReduction?` composes the resulting equivalence with
the existing parameter/arithmetic compiler. Its `ParameterReduction`
therefore proves or refutes the original source program, using the same
actual typed initial state and parameter witnesses as the leaf verifier.

`Examples/ProgramReduction.lean` checks both write verdicts, deletion,
default locals, nested block and branch scope restoration, a typed universal
parameter with an actual program, a failing decrement's initial value zero, guarded
requirements, false assertions under both modalities, condition-evaluation
failure, explicit revert, both branches and ignored panic. An explicit
checked counterstate also proves an original write claim invalid. Loops,
compound assignment, zero recognition fuel and exhausted shared budgets are
rejected. The headline
run bridge and original refutation use only Lean's standard three axioms.

This API does not compile all statement shapes. Its
normalized updates and leaves must still pass the existing exact checked
compiler, which excludes memory destinations, push-bearing updates,
dependent mapping keys and unsupported arithmetic. `#verify` now uses the
transaction-input extension below before its existing strategy and heuristic
refutation path.

## Exact calls and explicit witness layouts

`Calculus/SoundCalls.lean` now exposes the exact run equalities already
proved inside call soundness: `Stmt.runSt_callNone`, `runSt_callVal` and
`runSt_callRets`. The ordinary soundness lemmas reuse these equations.
They hold for arbitrary arguments and callee bodies, including every halt
outcome. Argument declarations read caller values in their original order;
return locals start at their defaults, then the callee frame is dropped or
thinned before the caller continues.

`ProgramNormalization.unfold` and `inline` turn those actual run equalities
into pointwise formula equivalences with the caller's remaining program and
frames. Call normalization uses the same argument/return declarations and
body weakening as the existing call expansion. It handles void calls,
scalar results assigned or discarded, and multiple returned primitive
locals. Recursive normalization of the expanded body shares the node budget;
unsupported body statements, reference-result calls or exhausted expansion
still return no complete arithmetic certificate.

`ParameterReduction.withLayout` exposes explicitly computed parameter and
reference lists only when both agree with the original reduction by checked
equalities. It retains the arithmetic formula and transports its width and
original-source meaning. This avoids unfolding a deep source recognizer
merely to infer the type of a finite witness literal; no recursion or
heartbeat limit was raised.

`Examples/CallReduction.lean` checks void, scalar, tuple and nested calls,
discarded results, default returns, distinguishable arguments and caller
local preservation. A failing argument reconstructs starting storage zero.
A false return claim reconstructs parameter 17 and has an explicit
kernel-checked original-call refutation. Panic and ordinary revert retain
their distinct behavior across call frames. The transaction-input extension
below connects actual `cspec` obligations to both certified verdicts.

and typed universal instance falsifying the original formula.

`declaration_input_reduce[φ]` composes independently certified declaration
normalization with this source compiler. Generated mapping premises disappear
