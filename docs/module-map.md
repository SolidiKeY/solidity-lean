# Module map

One line per module: what it defines. The module's own `/-!` docstring has
the detail; this file only says where to look. Source-support verdicts are
the [feature inventory](solidity-feature-inventory.md)'s; module presence alone
is not one.

**Start at `Theorems.lean`**: the main theorems on one page, in notation
(`⊢ φ → ⊨ᶠ φ`, `(P, σ) ⇓ o`, `⟦P⟧b`), each proved by the original's name.

```
Solidity/  KeySort  AST  Syntax  Semantics  Update  SpecSyntax  Theorems
           Semantics/         the interpreter's satellites
           Calculus/          the taclets and everything proved about them
           Theory/            solkey's data-structure theories, typed (Typed/), and their path side conditions
           Typing/            value typing, reachability
           SortCheck/         solkey's sort annotations, checked
           Counterexamples/   refutations that pin a design decision
           Evm/               the compiler and its simulation proof
           Tools/             the `#run`, `#wp`, `#verify`, … commands
           Corpus/            solkey's example suites (own target)
           Frontend/          solc's JSON AST read at elaboration time
           Solkey/            solkey's contracts imported from solc (own target)
           Examples/          the worked examples, in the default build
```

The library roots: `Solidity.lean` (the default build, every module),
`SolkeyTestSuite.lean` (solkey's `TestSuite.sol` imported and derived),
`SolidityCorpus.lean` (the generated corpus), `SolidityLean.lean` (the
native CLI entry point, `docs/cli.md`), `TrustAudit.lean` (the transitive
axiom gate of the public bridges).

| Root | What it builds |
|---|---|
| `Solidity.lean` | The `Solidity` library: every module of the default build. |
| `SolkeyTestSuite.lean` | `Solidity/Solkey/TestSuite.lean` and `Solidity/TestSuite/`. |
| `SolidityCorpus.lean` | `Solidity/Corpus/`, generated by `scripts/solkey-port.mjs`. |
| `SolidityLean.lean` | The native entry point of the CLI (`docs/cli.md`). |
| `TrustAudit.lean` | The transitive axiom audit of the public proof bridges. |

Layering: types and names (`AST`), contexts (`Scope`), the grammar and the
contract (`Syntax`), the typed syntax (`Syntax/Scoped`) and its elaborator,
the typed state (`Semantics/State`; storage `Semantics/Storage`, heap
`Semantics/Heap`) and the typed run (`Semantics/Run`),
terms and updates (`Signature`: the typed signature), scoped formulas (`Calculus/Fml`),
the taclets (`Calculus/Rules`), then what is proved about them
(`docs/intrinsic.md` has how it got this shape). Imports are acyclic; a new
module goes in `Solidity.lean` (`scripts/check-orphans.mjs` fails on a module
nothing imports).

**Formulas read storage through the Theory.** Programs run in the typed run,
an update is read by where it lands (`Upd.Lands`), but `a = b` (`Fml.eq`)
compares `Tm.denote`s in the typed Theory (`Theory/Typed/Obs.lean`: a storage
its observations at typed locations, `Storage.obs`) by `=`, and is total as
KeY's `=` is; a program comparison `a == b` is the same equation.  There is
no definedness test: what may revert is evaluated by the program, and
`wt(storage)` is a predicate (`Fml.wellFormed`).  `Theory/Typed/Obs.lean` proves once that the
interpreter's reads and writes are the Theory's (`Storage.obs_write`, …), and
`Theory/Bridge/Denote.lean` lifts it to the symbols (`OpN.denote_eval`).  A
derivation rewrites terms by named term taclets (`Calculus/TermLib/Rules.lean`,
`Proves.rewrite`), each sound by its Theory law (`TermTaclet.sound`).  `sol_decide`
reads the same Theory symbolically (`Calculus/Decide.lean`), and memory by
the typed laws of `Theory/Typed/Mem.lean` (`Calculus/MemRead.lean`).
