| `Yul/Layout/Alloc.lean` | `alloc`, the bump allocator of the layout view: the free-pointer word advanced by `allocSize`, then the tree written at the old free pointer (`allocAt`), refused below the reserved words or past `2 ^ 256`. A root `bytes` is `geometry.write` (the image of `byteAllocationView`), a root dynamic array its length word and elements. `put`, `putElems` and `putFields` write nested values inline and build the indirect header (length, data address) of a nested dynamic array or `bytes`, which `geometry.write` refuses, with the data out of line at a tail pointer advanced by `tailSize`. |
| `Yul/Layout/View.lean` | `view`, the one `Shrink.LayoutView` (`geometry` with `alloc`), and `view_geometric`, the transcription check `geometric` at that allocator. |
| `Yul/Layout/Laws/Alloc.lean` | `alloc_read` and `alloc_total`: the same-named `Shrink.LayoutView.Laws` fields at `view`. Read after allocation is a mutual recursion over the placed tree (`put_spec`): a placed value changes only the inline and out-of-line bytes it owns, and every state that agrees with the result there reads the tree back with a footprint inside them. Totality is `put_total` with the size bound `size_le` (at most 64 bytes per unit of `Tree.weight`). |
| `Yul/Layout/Laws.lean` | `view_laws : view.Laws`, assembled from `local_read`, `write_read`, `write_total`, `illTyped`, `frame`, `alloc_read` and `alloc_total`. |
| `Examples/YulLayout/View.lean` | Checks of the layout view: sizes and placements of the allocator on small trees, `view_geometric` on a packed element, both allocation laws as `Laws` fields at `view`, an allocation of `bytes[1]`, read after allocation of a `uint[][]` through `view_laws`, and the `byteAllocation` instance statement at `view`. |
