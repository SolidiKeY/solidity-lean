Lane: CR (memory-storage-copy), moved from the Codex VM lane to
`cloud/move6-20261106/cr-p8a` by H75 (2026-11-06). Base: the reviewed H68
metadata commit `7d86c162` (producer `scripts/solc-ast.mjs` keeps
`typeDescriptions.typeIdentifier` and `FunctionCall.tryCall` for modern
fixtures; explicit legacy fixtures keep their historical serialization).

This document states the contract a migration of the existing `solc_import`
route onto the canonical reader `Shared.executableReader` must meet, with the
checked evidence for each clause. It does not migrate the route, change either
reader, or add a fallback. The P8/P8b Producer modules (`Lowering/P8/*`,
Producer and admission modules) belong to `cloud/move5-20261106/p8-producer`
and are not touched here.

## Contract clauses

1. **Input (H68).** The canonical reader reads producer output with retained
   `typeIdentifier`/`tryCall`. Existing builtin-ID normalization and loop
   annotations are unchanged. Explicit legacy fixtures are not migrated; the
   canonical reader refuses them (missing `commonType`, missing identifiers),
   and that refusal is final.
2. **Fixtures.** Modern fixtures migrate only when the regenerated bytes equal
   the committed ones up to H68 fields (`exact`). `drift` fixtures (seven, all
   only extra `functionSelector` from a pre-H68 producer change that the
   importer consumes) and `no-source` fixtures (four: `CreationTry{,IR}`,
   `LibraryTry{,IR}`, whose upstream sources are not in this checkout) need
   their own decision. `--apply` rewrites only `exact` fixtures and their
   `solc_import` hash pins. It never rewrites another lane's sha256 manifest.
3. **Existing-route behaviour.** Migrated bytes must leave every existing
   `report` row's status unchanged. The one observed reason change (the
   `SliceReferenceCopies` `nominal` row) is a diagnostic refinement and must be
   recorded where that row is pinned.
4. **Support.** A migration of the actual printed-body/parser/macro route must
   not reduce the elaborated set. Today the canonical reader refuses narrow
   integers, `address`, `bytesN`, `string`, enums, structs, contract types,
   constructors and modifiers, and most expression and statement forms the
   existing route prints. The `uint8` probe is the minimal pinned witness.
   Closing this needs either reader support owned by the shared-translator
   owner (A) or an explicitly approved support reduction. A
   refuse-then-retry fallback is excluded ("errors are final").
5. **Diagnostics.** Canonical diagnostics (`compact verifier: …`, metadata
   messages) must surface through the existing row format
   `file:line: reason` with status `unsupported`. They must never become
   success or be replaced by the existing route's message for the same node.
6. **Provenance and admission.** `readImportedContract`'s source scan,
   settings, provenance, compiler code, calldata checks, source lines, return
   lowering, constructors, and modality/reference premises remain the
   admission authority. The canonical reader is a decoder, not an admission
   certificate (API-HANDOFF).

## Comparison recipe

For each `exact` fixture with a `solc_import` pin, import the committed bytes
and the `--apply` output side by side under fresh namespaces with the same
options and the same contract name (the last component of the import name),
and compare `toString (repr ….report)`. Run the scripts with
`--compiler DIR` holding the soljson files whose sha256 the headers record
(0.8.34 `c8649f8d…`, 0.8.38 `6c74ffba…`, the GitHub release assets), and
`--solkey-root DIR` holding `solkey-<commit>` checkouts for `473da894…`,
`575d04ea…` and `5c448df6…`, plus `no-solkey/keyext.solidity.core/build.gradle`
for the four fixtures that record `unknown`.
