## Cursor interface

`Source/FailureCursor.lean`, namespace `Source.FailureExecution`, defines
request/frame budgets indexed by `Fin issued` / `Fin started`, separate typed
stop kinds, a cursor, fresh ordinal allocation, owner-aware scope exit and event
budget advancement. A request requires actual quiescence evidence. Dropped
requests consume their ordinal but create no active budget. Frame pop retains
the ever-increasing counter and live ancestor counters; it does not restore an
old cursor snapshot. Request and frame IDs cannot consume each other's stops.

An active frame's event count is its observable activation subtrace, including
nested events. A pending request stop dominates; simultaneous frame cuts select
the oldest failing owner so a child cannot catch its parent's resource failure.
Already-stopped/zero-cut cursors do not advance. No event is emitted by the
cursor module. The actual emitter must check before appending, then advance and
unwind through the owner, preserving observed prefixes and actual rollback.

This module is not a second interpreter. Machine/Eval must execute the actual
existing code with these helpers, preserve request-level abort across child
handlers, use actual journal/heap rollback, and distinguish exceptional empty
revert from timeout/stuck and explicit full revert bytes. Receipt emission is
outside the active body budget. Transaction/frame ordinals must be stable in
the actual drivers, independently of action indices and depth.

`tests/source-failures/CursorControls.lean` freezes typed cursor expectations:
dropped/running requests, positive257 balance, nested IDs1/0, request-over-frame
priority, wrong-kind exclusion, outer-frame propagation through child pop,
retained ancestor counts, no ID reuse and zero-cut behavior. These are cursor
controls, not actual Source/EVM executions or a full failure-aware realization.
Routine projection/growth lemmas are delegated in TERRA-TODO; runtime soundness,
full source/physical/caller correspondence and all original24/six remain open.

Caller protocol remains explicit: the pure cursor permits arbitrary frame
entry/pop data operations, so actual Machine hooks must establish balanced
scope/ordered-ownership invariants and propagate an already-pending stop
before starting another body. Zero-cut checks belong at the actual frame
boundary before body execution; metadata allocation is not an observed event.
No proof of the runtime protocol follows merely from constructing a Cursor.
The exact declaration/axiom probe is generated by
`scripts/source-failure-interface.py`.
