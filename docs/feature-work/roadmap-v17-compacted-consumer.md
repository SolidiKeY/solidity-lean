# V17 compacted attachment consumer

The owned [consumer](../../scripts/roadmap-v17-verify-compacted.py) checks an externally SHA256-pinned final receipt.json, compact.json and syntax.unverified.json in one directory. Copies may be relocated together. Pending receipts and unverified compact paths are refused. The receipt binds attachment hashes, exact lengths, original input pin, supported schema, fixed ceilings and reported process limits. Impossible compaction lengths fail. Both attachments must be strict UTF-8 JSON with unique keys and finite JSON constants. Recompacting the syntax copy must reproduce the complete compact bytes, preserving numeric lexemes, order and every declaration field.

This is attachment consistency only. In the default attachment-only mode the original input is not reread: originalInputRechecked=false. Receipt contents, reported tool/process limits, revision, imports and native claims are not execution authentication. All six proof/execution/promotion flags remain false. An attacker able to supply new consistent pins can supply different data; this utility does not authenticate those pins or run a kernel verifier. Existing extraction and mandatory live replay remain necessary. No Docker/native verifier, fixed-ten Derived17 consumer or proof limit changes.

The retained real ForBreak attachments pass this consumer: 7605621 compact bytes, original input pin 840e8a47e411737f719c1c2cab2a384a3b9c47ec27e51d993fc38ea2b337f6d6. This is reuse of historical data, not a new same-revision proof observation. Host-only controls cover corrupted/missing attachments, wrong pins, contradictory promotion, changed ceilings, malformed fields, forged matching hashes, invalid token separation, duplicate keys, UTF-16/32, symlinks and pending/unlinked publication. Independent finder/skeptic reviews found UTF encoding autodetection, impossible counts and pending-path acceptance; all were fixed. The original compactor now explicitly decodes UTF-8 too, without modifying old receipts. One intermediate test failed because its mutation hit the new count guard before the intended byte-disagreement guard; the final mutation keeps the length and tests the intended path.

## Optional original-byte recheck

The consumer also accepts --original-input, with --original-member and --original-archive-sha256 paired when the original bytes are retained in an archive. It reuses the existing compactor execute path in a fresh private temporary directory, under the same CLI512MiB address-space and60CPU-second ceilings; it never resets these limits for the nested call. All regular-file identity, double-hash, archive/path/member, strict syntax and size checks remain in that single existing implementation. Library callers must supply the same bounded process context. Temporary compact/syntax copies are removed on exit, including failures. No permanent duplicate source/build/cache tree or archive extraction is created.

The entire recomputed bytes dictionary must equal the pinned receipt's dictionary: original byte hash/count, complete compact hash/count and syntax hash/count. A semantically equal JSON file with different whitespace is rejected as a different original. A relocated exact copy or an exact regular member in a separately pinned seal is supported. originalInputRechecked=true means that byte identity only; historicalFileIdentityAuthenticated=false explicitly excludes execution-time file identity. Original source revision, tool execution, imported objects, selectors, kernel proof, native replay, semantic premises and release closure remain unauthenticated. All six existing promotion flags remain false. Default mode and old sealed records are unchanged. No schema parsing or recovered bytes substitute for mandatory native authentication/replay.

The59 host-only controls include unchanged original compaction/attachment controls plus optional-mode regular/archived originals, wrong/missing member and archive pins, unsafe/link members, changed/missing/symlink originals, whitespace changes, paired locators and a contradictory original count that attachment-only mode correctly leaves unverified. The new mode rejects that contradiction after rereading the original. Independent read-only finder/skeptic source reviews report no findings.
