# V17 bounded retained-JSON compaction

[scripts/roadmap-v17-compact-json.py](../../scripts/roadmap-v17-compact-json.py) addresses an actual Backfill A review bottleneck: indented kernel records hundreds of megabytes long have exceeded the fixed512MiB parser address-space limit. This optional data consumer streams an externally SHA256-pinned regular file or an exact member of a separately pinned regular-file tar archive. It creates a new private output directory; it never rewrites the original, a seal, a cache or a proof engine.

The CLI enforces ceilings of512MiB address space and60CPU seconds without raising stricter inherited limits. Input is at most512MiB and minimal output16MiB. A separate syntax copy retains one ASCII separator per outside-string whitespace run; its bound2*16MiB+1 follows from the existing compact ceiling. This prevents invalid original tokens such as `[1 2]`, `t rue` or `- 1` from becoming accepted valid JSON after stripping. Quoted bytes, Unicode escapes, number lexemes, key order, complete arrays and proof fields are preserved. Duplicate decoded keys, non-JSON constants, invalid UTF8, truncation and trailing documents fail closed. Deep or otherwise unsupported inputs remain errors; no proof node/depth/recursion/fuel limit changes.

Archive mode validates the archive SHA, safe unique regular nonsparse member paths, selected member SHA and size bounds. Symlink/FIFO/device inputs are refused. Source file identity and hashes are checked before/after reading. Syntax and compact files are rehashed before publication. Failures retain unverified bytes and an error receipt where possible; compact publication rolls back if receipt commit fails. Consumers must require final receipt.json with status data-only and recheck the referenced compact hash. Pending receipts or a compact filename alone are not accepted output.

Exit0 means only that a bounded syntax-preserving data copy was produced. All kernelValidated, selectorsAuthenticated, replayVerified, semanticPremisesDischarged, releaseClosed and toolExecutionAuthenticated flags are false. Reported tool-source/Python-file hashes and observed process limits do not retroactively authenticate execution-time code, selectors, source revision, imported objects, original cgroups or native receipt ownership. Revision/tool/query/declaration claims inside the input remain claims for the existing native verifier. A failed gate, missing phase or forged success flag is preserved as data and never adopted as authority. This utility does not replace kernel extraction, mandatory replay, proof closure accounting or the Docker provenance verifier.

[38 controls](../../tests/roadmap-v17/test_compact_json.py) cover every chunk boundary, escapes/order/numeric lexemes, wrong input/archive/member pins, changed revision bytes, missing or mutated input/tool/output, unsafe/duplicate archive members, malformed split tokens, duplicate keys, limits, publication failure, failed-native records and forged proof flags.
