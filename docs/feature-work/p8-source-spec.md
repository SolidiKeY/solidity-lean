## Proved obstruction and precise missing implementation

`SpecExecution.no_countable_resource` proves that for any frozen Spec S and
FailureProjection S, functions `encode : S.lang.Res → Nat` and
`decode : Nat → S.lang.Res` with `∀ r, decode (encode r) = r` imply False.
The proof composes actual `S.failures_with` and `points_ofPoints` with the
transferred diagonal `no_horizon_retraction`. It does not assume an execution
result, weaken a premise, or prove correctness vacuously for an invented S.
The standard-axiom report is generated separately.

The actual `Source.sessionAtEvents` and `sourceLangEvents` still use `Nat`;
`sessionFromEvents`/`sessionGoEvents` do not accept request/frame FailurePoints,
and `dispatch`/`enterInstance`/`callAddr` have no independent frame-failure
resource argument. These operations must actually consult the supplied
resource before the full frozen realization can be implemented. A pair
`Nat × FailurePoints` alone is insufficient. Sender-funds validity is a
separate already implemented boundary and does not supply frame failure cuts.

A concrete SourceSpec and SourceOrigins additionally need a binding from the
actual resolved/elaborated frontend result to its `SrcProg` including fixed
parameters, pipeline and main contract. No such binding is silently chosen
inside this producer. CR source metadata/admission files remain untouched.
