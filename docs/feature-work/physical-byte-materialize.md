# Existing emitted byte materialization across both slices

`PhysicalByteMaterialize.lean` reuses `Environment.materialize`, its bounded PUSH immediates and actual emitted PUSH/MSTORE8 code. `materialize_suffix` proves its execution by the independent failure slice before an arbitrary suffix, using the reached memory recursively. `WordFrame.materialize_revert` combines the existing Environment runSlice result, actual failure-slice live REVERT, complete byte payload, stack tails and disjoint complete numeric-word frames. It assumes an initial WordFrame, the actual emitted interval fits, an exact represented length, and separation from the represented words. It does not assume a successful suffix or final byte relation.

The new controls use nonzero offset31, bytes [7,0,255], a populated protected high-bit word, complete six-byte boundary vectors and all32 protected bytes. Two actually executed overlapping programs produce [7,9,255] versus [7,0,255] in opposite order. Empty materialization is a real no-op. Unsupported MLOAD after a successful materialization returns none; short-stack MSTORE8 also returns none. Neither failure invents a returned machine. The two backend APIs have no Source pipeline parameter.

The component does not supply a concrete PhysicalByteWorldInterface.Producer, abstract numeric MSTORE8 instruction refinement, Source/ABI/world/transaction rollback, gas, stack-height, active extent, allocation or external compiler/EVM adequacy. Pending whole-lane gates and all original queue obligations remain open. Independent source/artifact review and exact guard receipts accompany the checkpoint.
