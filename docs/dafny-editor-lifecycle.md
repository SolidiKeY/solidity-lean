# Editor lifecycle probes

Related original scope: [Dafny editor parity](dafny-editor-parity.md).

For source-only launch-argument observations, run
`node vscode/parity/lifecycle-trace.cjs --launch-arguments NEW_OUTPUT.json`.
This requires the pinned extension checkout, its TypeScript dependency and the
restored checksum-bound inventory. Wrong revisions, dirty tracked sources and
files differing from immutable Git blobs are refused before execution. It
executes the original client builder with injected configuration and installer
boundaries. It never starts a server or loads a plugin. Explicit bounded fixture
settings are not observations of native defaults, and malformed plugin inputs
exercise the builder only. The compiler must be absent from the module cache;
its exact recorded file and the schema bytes are verified before use. Native
configuration/restart, plugin loading, ghost decorations, local correspondence
and both independent row judgments remain separate unfinished obligations.


For native resolver-only ghost notifications, run
`node vscode/parity/lifecycle-trace.cjs DAFNY_EXECUTABLE NEW_OUTPUT --ghost`.
The observer reads the exact pinned on/off C# test sources and expected range.
Each fresh server uses Never verification, one core, the existing20-second
verifier limit,4GiB process-tree RSS cap, no swap and12GiB host reserve. It
requires owned ResolutionSucceeded and query checkpoints; a symbol response
alone is insufficient. On-mode checks the latest range, UTF16 comment movement
and restoration; off-mode requires zero ghost notifications through shutdown.
The distinct pinned on/off source fixtures are not a same-source A/B comparison.
No VS Code decoration, local ghost semantics or kernel proof follows.


For reference-only terminal-prefix construction, run
`node vscode/parity/lifecycle-trace.cjs --terminal-prefix NEW_OUTPUT.json`
with an external output path. The pinned registered Build callback uses injected
editor, installer, OS and terminal endpoints. Cases cover null versus empty
prefixes, literal configured prefixes and cwd, terminal reuse and early save
refusals. No terminal command executes; simulated Windows is not native Windows
coverage. Existing quoting and unquoted cwd text remain observable differences.
Local terminal-prefix support and full native/lifecycle/judgment evidence remain
unavailable. Failed receipts stay failed after serialization.


For compiler-only native diagnostic API observations, run the existing Linux
native supervisor/display with
`node vscode/parity/run.cjs --code PINNED_CODE --suite related-diagnostics --targets local --workers 1 --cache none --trials 1 --warmups 0 --obligations 1 --trace on --output NEW_OUTPUT`.
The companion keeps the existing60s operation/300s outer budgets and4GiB
sampledRSS/no-swap/12GiB host-reserve guards. It copies public diagnostic getters
through duplicate, UTF16/CRLF-shift and fixed phases, binding current document
and process epochs to the actual recorded compiler wire. This is not a native
key/menu dispatch, rendered Problems/underline capture, postcondition proof,
Dafny comparison or either independent row judgment. Missing or failed captures
retain their full partial observation; original suites and predicates remain.

The separate `--diagnostic-input public-eol-v1` companion uses the public
`TextEdit.setEndOfLine` API to establish exact CRLF shifted bytes and restore LF
for the fixed phase. The original implicit mixed-ending path and its strict
expectations remain unchanged; its failed native receipt remains failed. Input
profiles are checked against trusted launch configuration, not inferred from
observed text or normalized during validation. All budgets and missing aspects
above remain.

A separate `--diagnostic-lifecycle ui-open-close-v1` companion, together with
`--diagnostic-input public-eol-v1`, uses registered `vscode.open` rather than
acquiring an API-open model reference. The pinned editor source gives that
API reference a three-minute default lifetime. The companion still requires an
actual owned document-close event, typed public tab/model endpoints and LSP
close, then a different document/synchronization lifetime on reopening the same
URI and saved bytes. Tab disappearance alone never establishes closure. The
original API-open close failure, trust-recovery predecessor, budgets and row
judgments remain unchanged; this is not a native-key or rendered proof claim.


The separate `--diagnostic-events public-v1` companion requires
`--diagnostic-input public-eol-v1` without the close/reopen companion. It records
actual public `languages.onDidChangeDiagnostics` callbacks through the existing
observer registration, adding owned source/session/wire getter snapshots,
including foreign/unavailable resources, under the existing phase deadlines.
Current callback snapshots must agree with source/document/synchronization-owned
compiler wire publications. This is observation-time correlation, not proof of
which notification caused the callback. The pinned upstream test's failing
postcondition fixture remains a distinct verification obligation; compiler
errors cannot substitute for that test, rendered Problems or either row judge.


The separate `--diagnostic-rendered problems-v1` companion additionally requires
`--diagnostic-events public-v1` and captures duplicate/shifted/fixed Problems
states through the existing phase transport. It opens the registered Problems
view without executing product proof/build commands. The renderer keeps the
three-second readiness and five-second CDP guards, expands only hit-owned view
rows, and brackets AX/DOM/PNG with equal visible-state samples. Host API/source
and current diagnostic-publication fences remain separate from the observed
active editor URI. Problems row IDs are opaque: an independent Problems resource
URI, full range-end/raster/occlusion correspondence, paired Dafny/macOS and both
row judgments remain unavailable. Matching labels do not close those gaps.


The separate `--diagnostic-rendered problems-scroll-v2` collection records
primary and related-information viewports independently. A native wheel is
allowed only at an observed owned Problems scrollport with the same source and
renderer lifetime. Both preparations share one absolute three-second deadline;
that budget is not restarted after the first snapshot. Each viewport retains
its own before/after AX/DOM/PNG bracket under the original operation deadline.
The failed same-viewport v1 case and its predicate remain unchanged. Separate
viewport observations do not establish simultaneous visibility, complete text,
resource URI attestation, raster equivalence or either original row judgment.
The scroll companion's DOM probe additionally handles translation-only virtual
list transforms using observed post-transform rectangles, while rejecting scale,
rotation and perspective on every ancestor. The v1 transform predicate is
unchanged. This is collection geometry, not a new parity acceptance rule.
